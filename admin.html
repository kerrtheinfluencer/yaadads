What Hide does

Hide sets the listing's status to hidden. It leaves the homepage, search, the category counts, the AI chat, similar listings and the member's own My Ads list, and the next page-generation run deletes its /ad/… page and sitemap entry. The row stays in the table, so Restore puts it straight back. Use Delete only when the post should be gone for good.

  • Hide all on a row hides every live listing from that same member — the fastest way to clear a spam run.
  • Hidden posts are invisible to members too, so the seller sees the listing disappear from My Ads. Restore it if you change your mind — nothing is erased.
  • Nothing here is real authentication. This page writes with the public anon key, which is only allowed to change rows because the project still carries the legacy anon can update/delete ads policies. If those are ever tightened, actions fail loudly instead of pretending to work.

What the Reports queue does

Members tap Report this listing on any ad and pick a reason. That posts to a real table now, so it arrives here — grouped by listing, newest first, carrying every reason members gave.

  • Hide takes the reported ad off the site and clears its reports. Reversible via the Hidden filter.
  • Delete removes the ad for good. Confirm-gated.
  • Hide all N clears a whole spam run from one member, then clears only this ad's reports — the rest stay queued for review.
  • Dismiss clears the report and leaves the ad alone, for when the report itself is wrong.
  • A report row existing means it still needs attention. Hiding or deleting an ad from the Listings panel above clears its reports too, so the two panels can never disagree.
  • It never shows who reported what. The queue reads a view that omits the member id and the device key, so this page cannot deanonymise a reporter even by accident.
  • Needs supabase-migration-ad-reports.sql run once in the Supabase SQL Editor. Until then this panel says exactly that, rather than showing an empty queue that looks like "all clear".
